# Do Diffusion Language Models Provide Useful Verification Diversity?

**CSCI 544 (Applied NLP, USC, Fall 2026) · Team "project 16" · Research-focused**

> **Original project design (September 22, 2026).** This is the idea the project is built on, kept as written. The current plan is [PLAN.md](PLAN.md); its §13 lists every change from this document and why.

**One-line summary:** At a matched acceptance rate for correct answers and comparable inference cost, does an AR+diffusion verifier pair falsely accept fewer wrong answers than the strongest AR+AR pair?

---

## 1. Background and motivation

LLMs are routinely used as **verifiers** of other models' outputs — as judges, rerankers, best-of-n selectors, and oversight components. The standard way to strengthen verification is to ensemble multiple verifiers, but prior work (Weaver: Saad-Falcon et al., 2025) shows a ceiling: strong autoregressive (AR) models make **correlated mistakes**, so each additional similar verifier contributes mostly redundant signal. Related work on model similarity (Goel et al., 2025, which introduced the CAPA metric) argues this correlation actively undermines AI oversight.

**Diffusion language models** (LLaDA-8B, Dream-7B, LLaDA 2.0-mini) learn text through global denoising rather than left-to-right prediction. That is an _objective-level_ difference — a plausible source of genuinely decorrelated errors, unlike swapping between AR families that share the same training objective. Existing diffusion-verification work runs in other directions (diffusion self-checking, e.g. PRISM/HIVE; diffusion drafting for AR verification, e.g. DEER/FreeCache — see the team's vetting notes). **Nobody has tested diffusion models as verifiers of AR outputs against matched AR baselines.**

### The gap, stated precisely

No published work measures whether crossing the AR/diffusion training boundary yields **decorrelated verification errors at matched competence** on AR-generated candidates. That is the question this project answers.

## 2. Hypotheses

- **H1 (primary):** At matched true-accept rate (TAR) on correct candidates, an AR+diffusion verifier pair has a lower joint false-accept rate (FAR) on incorrect candidates than the best AR+AR pair from different model families.
- **H2 (mechanism):** Chance-adjusted error overlap (CAPA / Cohen's κ on mistakes) is lower across the AR/diffusion boundary than across AR families.
- **Interpretation is guarded:** off-the-shelf model comparisons license claims about _model pairs_, not about the diffusion objective causally. Shared-lineage controls (where feasible) are needed before any causal claim about the training objective.
- **A negative result is informative:** "changing model class buys no complementarity beyond strong cross-family AR baselines" is a useful, citable finding given current interest in diffusion LMs' complementary strengths.

## 3. Experimental design

### 3.1 Frozen candidate bank (the core methodological device)

A fixed set of (problem, candidate answer, ground-truth label) triples that **every verifier judges identically**, enabling paired, apples-to-apples comparisons. Everything downstream is conditional on identical inputs.

- **Tasks (independently checkable only):**
  - Math: GSM8K / MATH-style problems — answer-checkable against ground truth.
  - Code: MBPP / HumanEval-style problems — execution-checkable against unit tests.
- **Candidates:** generated by 3–4 AR generators of varied strength so the bank contains _realistic_ errors (natural wrong answers models actually produce), not synthetic corruptions. Target mix: roughly balanced correct/incorrect after labeling.
- **Labeling:** fully programmatic (answer match / test execution). No human labels in the main bank. A smaller, controlled reasoning-trace subset may be added later for error-type analysis only.
- **Size:** 500-item pilot → 2,000–5,000 at full scale.
- **Freezing:** once labeled, the bank is versioned and never modified mid-experiment. All results reference a bank version hash.

### 3.2 Verifiers

- **AR verifiers (2–3 families, deliberately different lineages):** Qwen2.5-7B-Instruct, Llama-3.1-8B-Instruct, Gemma-2-9B or Mistral-7B-Instruct.
- **Diffusion verifiers (1–2):** LLaDA-8B-Instruct, Dream-7B(-Instruct).
- **Primary interface — direct verdict scoring:** identical prompt template asking each verifier to judge the candidate (accept/reject + confidence). Verdict extraction must be robust across 2–3 prompt formats (a pilot-gate requirement).
- **Secondary ablation — reconstruction/denoising scoring** for diffusion models (masked-reconstruction likelihood of the candidate given the problem), since verdict prompting may under-use the diffusion objective.
- **Baseline structure:** the strongest AR+AR pair uses _different model families_ (not related checkpoints), so the diffusion comparison must beat honest diversity, not a strawman.
- **Shared-lineage control (where feasible):** an AR and a diffusion model derived from related lineage, to reduce training-history confounds.

### 3.3 Metrics

| Level           | Metric                                   | Purpose                     |
| --------------- | ---------------------------------------- | --------------------------- |
| Single verifier | ROC / AUC                                | Discrimination quality      |
| Single verifier | Calibration (ECE, reliability curves)    | Are confidences meaningful? |
| Single verifier | GPU-seconds per candidate                | Empirical cost accounting   |
| Pair            | Joint FAR at matched TAR                 | **Primary outcome (H1)**    |
| Pair            | CAPA / κ on mistakes                     | Error decorrelation (H2)    |
| Pair            | Ensemble gain curves (accuracy vs. cost) | Practical payoff            |

- **Matched operating points:** thresholds chosen per verifier to equalize TAR before comparing pairs — prevents mistaking weakness for diversity.
- **Statistics:** bootstrap CIs over candidates; results stratified by task type, generator, and error type; paired comparisons throughout (same candidates).

### 3.4 Known failure modes and controls

- _Incompetent disagreement:_ a weak verifier disagrees uselessly → enforce matched marginal competence (analysis restricted to operating regions where the diffusion verifier meets a minimum AUC bar).
- _Prompt sensitivity:_ verdicts must be stable across prompt variants → measured in the pilot.
- _Label noise:_ only programmatically checkable outcomes in the main bank.
- _Confounds (data, post-training, lineage):_ causal claims kept modest; shared-lineage arm where feasible.

## 4. Pilot and go/no-go gate

**By the end of the pilot (target: week of Sep 29 – Oct 6):**

1. 500-candidate bank built and labeled across both task types.
2. Common verifier interface running on all selected models.
3. **Gate criterion A:** each diffusion verifier achieves standalone discrimination meaningfully above chance and within striking distance of a small AR verifier (else its "diversity" is noise).
4. **Gate criterion B:** verdict extraction is stable across prompt formats.

**If the gate fails:** pivot to an **AR-family error-diversity study** on the exact same frozen bank — which families disagree most, and does cross-family ensembling approach the oracle? The full pipeline investment (bank, harness, metrics, statistics) carries over unchanged. This pivot is declared in the proposal and should be referenced in the midterm report either way ("we defined a gate; here is what passed it").

## 8. Risks and pivots (mirrors the proposal, with the gate restored)

1. **Diffusion verifiers too weak/miscalibrated** → pilot gate (Section 4); fallback: AR-family diversity study on the same bank.
2. **Confounding from training data/lineage** → modest causal claims; shared-lineage controls where possible.
3. **Label noise on reasoning traces** → main bank uses only programmatically checkable outcomes; reasoning analysis kept small and controlled.
4. **Iterative diffusion scoring too expensive** → direct verdict scoring is primary; reconstruction is an optional ablation.
