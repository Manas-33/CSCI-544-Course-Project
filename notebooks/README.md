# Colab notebooks (stage 3: finish the scoring-code tests)

Each notebook runs in its **own fresh Colab runtime** (the model environments conflict), on an **A100**. Open it from GitHub in Colab (*File → Open notebook → GitHub*), run all cells, and download the zip at the end. Unzip it into the repo at the same path (`results/stage3/<name>/`) and commit it, or send it over.

| Notebook | Environment | What it settles |
|---|---|---|
| `01_ar_verifiers.ipynb` | `requirements.txt` (transformers 4.51.3) | Sanity check for Llama-3.1-8B, Gemma-2-9B, Llama-3.2-3B and Qwen2.5-1.5B; the AR reference check for every AR model (the sign-off behind Mistral's failure); Qwen and Mistral on the 71 development pairs. Llama, Gemma and Mistral are gated: accept their licenses, and add a Hugging Face token as the Colab secret `HF_TOKEN`. |
| `02_llada.ipynb` | `harness/diffusion/requirements/llada.txt` | LLaDA's test 2 (parity with the official code) and test 3 (invariance), its sanity check through the shared scorer, and agreement with the saved LLaDA run. |
| `03_illada.ipynb` | `.../illada.txt` (transformers 4.57.1) | iLLaDA's answer-slot count on the development bank, the usable-scores gate, and tests 1–3. |
| `04_dream.ipynb` | `.../dream.txt` (transformers 4.46.2, torch 2.5.1; restart the session after installing) | Dream's answer-slot count, the usable-scores gate, and tests 1–3 (test 2 is also its shift check). |

Each notebook clones `main` by default; set `BRANCH` in the first code cell to test another branch. Shell lines use `{VAR}` for Python variables (IPython reads `$N.json` as attribute access and leaves the line unexpanded).

**Reading the output.** Every check prints PASS or FAIL and writes a JSON report either way. A FAIL is a result, not a crash. Under PLAN.md §4, a model that fails the sanity bar (test 1) after its code passes the reference checks counts as a weak verifier (a gate A failure), not an open bug. The development-bank scores are pipeline checks, never results (PLAN.md §2).

The notebooks are generated by `notebooks/make_notebooks.py` (run `python notebooks/make_notebooks.py notebooks` from the repo root); edit the generator, not the notebooks. `harness/test_notebooks.py` checks they are up to date, that every shell line expands in IPython, and that every flag exists in the script it calls.
