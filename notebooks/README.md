# Colab notebooks (stage 3: finish the scoring-code tests)

Each notebook runs in its **own fresh Colab runtime** (the model environments conflict), on an **A100** unless its paragraph below says otherwise. Open it from GitHub in Colab (*File → Open notebook → GitHub*), run all cells, and download the zip at the end. Unzip it into the repo at the same path (`results/stage3/<name>/`) and commit it, or send it over.

Notebooks 05–08 built and scored the pilot bank (`results/pilot/README.md`).

**Step 0 of the go/no-go:** `09_step0.ipynb` (A100 or L4; about an hour on an A100, an L4 is roughly three times slower per pass; cells in `nb_step0.py`) scores the answer-swap items with every verifier, the H1 models first, and the pilot bank twice with the AR models, then runs `analysis.step0`. It saves to Google Drive (`MyDrive/cs544_step0/`) after each step, continues after a disconnect, and gives the GPU back at the end. Unzip `step0_results.zip` into the repo and commit `results/step0/`.

**The full bank and the backup score.** `10_full_generate.ipynb` writes the full bank's answers: the three open models on an A100 (about two hours), GPT-4.1-mini by API in a separate CPU runtime. `11_full_label_split.ipynb` labels them, builds the bank and splits it; it runs on a CPU, and **only the label keeper** (role F in PLAN.md §2, who takes no part in scoring, selection or thresholds) runs it. Cells of both are in `nb_full_bank.py`. `12_backup_score.ipynb` (A100 or L4; cells in `nb_backup_score.py`) scores the pilot's math answers with LLaDA's reconstruction score and says whether it passes as the repair (PLAN.md §7); Dream, the AR arm and the math-bank side experiment are switches. Both pilot seeds must come from one GPU type, and so must all full-bank scores, notebook 13's included ([record](../decisions/2026-11-22-scoring-one-gpu-type.md)). All three save to Google Drive, continue after a disconnect, and release the runtime at the end.

**Scoring the full bank.** `13_score_full.ipynb` (A100 or L4; cells in `nb_score_full.py`) scores both splits of both banks with T1 and T2 and all eight verifiers, one model group per section; math and code can be run one at a time. The guards, commands, saving and completeness check are in `harness/full_run.py`: nothing is scored before the final model record and the bank freeze are merged, and every run has to be on the GPU type of the first one. It saves to Google Drive (`MyDrive/cs544_full_scoring/`) after each run, continues after a disconnect, and gives the GPU back at the end. Unzip `full_scores.zip` into the repo and commit `results/full/` when the check says complete. It always uses `main`.

Each other notebook clones `main` by default; set `BRANCH` in the first code cell to test another branch. Shell lines use `{VAR}` for Python variables (IPython reads `$N.json` as attribute access and leaves the line unexpanded).

**Reading the output.** Every check prints PASS or FAIL and writes a JSON report either way. A FAIL is a result, not a crash. Under PLAN.md §4, a model that fails the sanity bar (test 1) after its code passes the reference checks counts as a weak verifier (a gate A failure), not an open bug. The development-bank scores are pipeline checks, never results (PLAN.md §2).

The notebooks are generated by `notebooks/make_notebooks.py` (run `python notebooks/make_notebooks.py notebooks` from the repo root); edit the generator, not the notebooks. `harness/test_notebooks.py` checks they are up to date, that every shell line expands in IPython, and that every flag exists in the script it calls.
